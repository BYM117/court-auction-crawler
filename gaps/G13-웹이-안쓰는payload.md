## ⚠ 실거래가는 지금 상태로 그냥 붙이면 안 된다 — 이게 더 중요하다

`transactions`의 건물 매칭률을 실측했다.

| | 그 건물 매칭 | 동네 평균만 |
|---|---|---|
| 매매 | **664 (3.5%)** | 18,577 |
| 전월세 | **1,001 (5.2%)** | 18,240 |

**96.5%가 그 건물 실거래가 아니라 동네 평균이다.**
그런데 필드 이름은 `transactions`이고 `building`에 건물명이 들어 있다.

```json
{"type":"villa","building":"에스아이팰리스센트럴성내",
 "sales":{"matched":false,"count":880,"min":11000,"avg":47006,"max":360000,
          "recent":[{"name":"금성빌리지2차","area":62.09,"floor":"3","amount":40000,"date":"2026-07-31"}...]}}
```

`matched: false`인데 `building`에 건물명이 붙어 있어서, 화면에 무심코 얹으면
**"이 건물 실거래가"로 읽힌다.** 경매 입찰가 판단에 직결되는 숫자라 오해 비용이 크다.

**웹이 안 쓰고 있던 게 오히려 다행이었다.**

## 고치는 법

**세션 B (우리 쪽 숙제)**
1. **매칭률 3.5%를 끌어올린다.** 건물명 정규화 · 면적 대조 · PNU 기반 조회를 검토한다.
   **이게 안 고쳐지면 꽁지맵이 뭘 만들어도 틀린 숫자를 예쁘게 보여주는 것뿐이다.**
2. `property.share`를 `special_rights`에도 넣는다.
3. `G07`의 `case_type`도 함께 싣는다.

**세션 D (꽁지맵)**
4. `sales.matched` / `rent.matched`를 **화면에 반드시 드러낸다.**
   매칭이면 "이 건물", 아니면 "○○동 평균(880건)"처럼 범위를 명시한다.
   **이 구분 없이 붙이는 것은 하지 말 것.**
5. 목표는 네이버 부동산처럼 **"언제, 얼마에 팔렸다"**를 보여주는 것이다.
6. `coordinate_quality`를 써서 `approximate`는 "대략 위치"임을 드러낸다(`G12`).
   **2026-09-17로 값이 늘었다.** G12를 고치면서 핀에 등급이 생겼다 —
   `coordinate_source`가 `address`(지번 정확) · `building`(건물명) · `lot`(옆 필지,
   부번이 지도에 없어 본번으로 잡은 것) · `district`(리·동 단위, 어업권·건설기계처럼
   지번이 아예 없는 물건) · `none`(좌표 없음)이고, 뒤 셋은 `quality='approximate'`
   또는 `'missing'`이다. 현재 활성 기준 근사 25건 · 위치 미상 6건.
   **위치 미상은 지도에서 빠지되 목록에는 '위치 미상'으로 남아야 한다**(사용자 결정).
   `lot`·`district`는 PNU가 비어 있으니 공시가격·실거래 비교를 붙이면 안 된다.
7. `property.share`를 직접 쓴다.

> 2026-09-16 사용자 방침: *"웹이 이 값을 잘 쓸 수 있게 해야지, 옥션원처럼."*
> **payload에 실어 보내는 것으로 끝이 아니다. 꽁지맵 쪽 작업이 짝으로 필요하다.**

## 2026-09-17에 늘어난 것 — 세션 D가 받을 두 덩어리

**① 보증금 (`auction.deposit`) — 돈에 직결된다.**

```json
"deposit": {"amount": 1711400, "rate": 0.2}
```
`rate`가 **0.1을 넘으면 화면에서 경고**해야 한다. 재매각 물건은 매수신청보증금이
최저가의 20%(때로 30%)라, 모르고 10%만 준비해 가면 **입찰이 그 자리에서 무효**다.
활성 641건이 해당한다. **비율을 추정하지 말 것** — 법원이 적은 금액을 그대로 싣는다.
'재매각이면 20%'는 27%에서 틀린다(`G04`).

**② 재매각 이력 (`auction.resale`).**

```json
"resale": {"is_resale": true, "reason": "대금미납", "status_flow": "매각준비 -> … -> 대금미납"}
```
활성 462건(대금미납 388 · 매각불허 74). `special_rights`에도 `재매각`이 붙는다.
보증금과는 **겹치지만 같지 않다**(둘 다인 것 208건). 따로 보여줘야 한다.

**주의** — 이 두 필드는 **목록(snapshot)에 먼저 실린다.** 스냅샷은 매번 통째로 다시
만들기 때문이다. 물건별 상세 파일(`v1/items/*.json`)은 그 물건이 갱신될 때 따라간다.
전량을 당장 맞추려면 `web_sync`의 `kind='item'` 행을 지워야 하는데 763MB 재업로드다
(`CLAUDE.md` 함정 ②). 급하지 않으면 두고 보는 쪽이 싸다.

## 세션 B 숙제 1번을 했다 — 매칭률 3.5% → 38% (2026-09-17)

### 진짜 병목은 이름 비교가 아니라 **이름 추출**이었다

| | |
|---|---|
| 실거래 붙은 활성 물건 | 23,979 |
| 그중 단지명이 **뽑힌** 것 | 3,160 (**13%**) |
| 매매 매칭 | 673 (2%) |

`_building_name`이 **괄호 안만** 봤다. 법원 주소의 절반은 지번 형식이라 건물명이
괄호 밖에 있다 — `군산시 소룡동 1323-13 동아아파트 107동`. 이건 통째로 놓쳤다.
지오코더의 `_extract_building_hint`가 이미 둘 다 하므로 그것을 쓴다(13% → 50%).

### 그런데 이름을 잘 뽑아도 한계가 있다

법원이 쓰는 이름과 국토부가 쓰는 이름이 **애초에 다르다.**

```
법원  가산양우내안애애플     국토부  가산양우내안에애플     ← 애 / 에
법원  달동엠타운           국토부  달동 M타운           ← 엠 / M
```

정규화를 아무리 얹어도 `애`와 `에`는 못 붙인다.

### 이름을 버리고 **필지**로 댄다

실거래 응답에는 행마다 `umdNm`(법정동)과 `jibun`(지번)이 붙어 온다. 우리도
지오코딩 때 같은 것을 받아 저장해 뒀다.

| 열쇠 | 활성 물건 보유율 |
|---|---|
| 정규화주소의 동+지번 (`verified`) | **97%** |
| PNU 19자리 | 99% |
| 단지명 (고치기 전) | 13% |

추가 API 호출은 없다. **이미 받아온 응답에 들어 있는 필드다.**

**주의: 지번만 대면 안 된다.** 한 시군구 안에 같은 지번이 동마다 있다.
법정동까지 같아야 같은 필지다 — 이 함정을 측정 스크립트가 먼저 밟아,
지번만 댔을 때 40%가 법정동까지 대니 34%로 내려갔다.

### `matched` 불리언 하나에 네 가지가 뭉개져 있었다

이제 `match_level`이 어디까지 좁혔는지 말한다.

| 수준 | 뜻 | 실측(표본 71건) |
|---|---|---|
| `parcel` | 같은 필지 — 이 물건이 있는 바로 그 땅 | 23% |
| `name` | 같은 단지명 | 14% |
| `dong` | 같은 법정동 — 동네 시세 | 21% |
| `sigungu` | 그냥 그 구 전체 | 40% |

**앞의 둘(38%)만 이 물건의 값이다.** `matched`는 그 둘일 때만 참이다.

### 문서가 틀렸던 것 두 가지

**① `matched: false`는 "인근(법정동) 전체"가 아니었다.** 조회 단위가 `pnu[:5]`라
**시군구 전체**였다. 그 풀의 크기를 쟀다 — 최소 1 · 25% 301 · **중앙 774** ·
75% 1,258 · 최대 4,143건. 중앙값 774건이면 동네가 아니라 구 전체다.
화면이 옛 주석대로 `○○동 평균`이라 쓰면 **거짓말이 나간다.**
이제 필지도 이름도 못 맞추면 적어도 `umdNm`으로 **법정동까지는 좁힌다**(공짜다).

**② payload 경로는 `property.transactions`가 아니라 최상위 `transactions`다.**
세션 D는 여기를 봐야 한다. 실려 오는 모양:

```json
"transactions": {
  "type": "villa", "building": "동아아파트", "parcel": "소룡동 1323-13",
  "sales": {"matched": true, "match_level": "parcel", "count": 3,
            "min": 11000, "avg": 47006, "max": 360000, "recent": [...]},
  "rent":  {...}
}
```

### 세션 D가 화면에 써야 하는 것

`matched` 불리언 말고 **`match_level`을 그대로 읽어** 범위를 밝힌다.

| `match_level` | 화면 문구(예) |
|---|---|
| `parcel` | **이 건물 실거래** |
| `name` | 같은 이름 단지 실거래 |
| `dong` | ○○동 시세 (N건) |
| `sigungu` | ○○구 시세 (N건) — **이 물건 값이 아니다** |

### 남은 것

- **기존 데이터는 옛 모양이다.** 활성 `transactions_status='ok'` 20,166건은
  `list_missing_enrichment`가 다시 안 잡는다(성공한 것은 후보가 아니다).
  새 모양을 입히려면 그 행들의 status를 되돌려야 한다 — `CLAUDE.md` 함정 ②와
  같은 종류다. 빈값 9,592건은 그냥 두면 새 코드로 채워진다.
- `sigungu` 40%는 그 동에 최근 거래가 아예 없다는 뜻이다. 기간을 6개월에서
  넓히면 줄어들 것이나 API 호출이 배로 는다. 재기 전에는 고치지 않는다.
- 숙제 2·3번(`property.share`를 `special_rights`에, `case_type` 싣기)은 아직이다.
