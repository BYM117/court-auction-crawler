# G09. 수집이 '기일입찰'로 걸러진 채 돌고 있다 — 지금은 손실 0, 조용한 지뢰

**상태**: **해결됨** (확인·수정 2026-09-17, 세션 B) · **담당**: 세션 A→B

## 한 줄
**지금 잃는 건 0인데, 제도가 재개되면 에러도 경고도 없이 조용히 잃는다.**

## 원인 (실제 화면으로 확인, 2026-09-16)
물건상세검색과 매각예정물건 **두 화면 모두** `입찰구분` 라디오가 있고 **기본값이 `기일입찰`** 이다.

```
물건상세검색  rad_mvprpBidLst_input_0        title="기일입찰"  checked  ← 기본값
              rad_mvprpBidLst_input_1        title="기간입찰"
              rad_mvprpBidLst_input_2        title="전체"

매각예정물건  rad_dspslSchdGdsBidLst_input_0 title="기일입찰"  checked  ← 기본값
              rad_dspslSchdGdsBidLst_input_1 title="기간입찰"
              rad_dspslSchdGdsBidLst_input_2 title="전체"
```

**우리 코드는 이 라디오를 어디서도 건드리지 않는다.**
`grep -rn "BidLst|입찰구분|기간입찰" src/ tests/` → 0건.

## 지금 실제 손실은 0이다
- 옥션원 기간입찰 페이지 공지: *"전국 법원에서 시범적으로 실시하던 기간입찰이
  서울서부지방법원을 마지막으로 종료되었습니다."* 달력도 전부 비어 있다.
- 우리 활성 상세 6,000건 표본의 `입찰방법`이 **전부 `기일입찰`**.
- `기간입찰` 문자열이 걸린 4건은 실물이 아니라 문건처리 내역의 **`기간입찰불능조서 제출`** 기록이다
  (2026.01·2026.05에도 있다 — 절차 어휘로는 살아 있다).

## 그런데 조용하다. 그게 문제다
기간입찰이 재개되면 그 물건들은 **에러도 경고도 없이 그냥 안 들어온다.** 행이 줄 뿐이다.
`CLAUDE.md` 함정 ④("창이 망가지면 조용히 0건이 된다")와 같은 종류인데,
이쪽은 **연속 0건 감시에도 안 걸린다** — 애초에 존재를 모르니까.

## 고치는 법
두 화면에서 `입찰구분`을 **`전체`** 로 바꾼다. 라디오 하나씩 **두 줄**이다.
`SearchPageConfig`에 셀렉터를 얹으면 화면 4종 분기 방식과 맞는다.

**WebSquare는 신뢰된 클릭만 받으므로** JS가 아니라 Playwright `locator.click()`을 써야 한다
(`_go_next_page`·`G08`과 같은 문제).

> 지금 고쳐도 수집 결과는 안 변한다. **재개될 때 조용히 잃지 않으려고 미리 박아두는 것이다.**

## 고치기 전에 확인했다 (사용자 요청, 2026-09-17)
`전체`로 바꾼 뒤 **같은 조건으로 두 번 검색해 건수가 같은지** 봤다.
같으면 지금 기간입찰 물건이 정말 0이라는 뜻이고, 다르면 이미 잃고 있었다는 뜻이다.

| 화면 | 법원 | 기일입찰(기본값) | 전체 | |
|---|---|---|---|---|
| 진행 | 서울중앙지방법원 | 223 | 223 | 같음 |
| 진행 | 수원지방법원 | 734 | 734 | 같음 |
| 진행 | 부산지방법원 | 271 | 271 | 같음 |
| 예정 | 서울중앙지방법원 | 첫 장 8행 | 첫 장 8행 | 같음 |

**전부 같다. 지금 잃고 있던 것은 없다.** 문서에 적힌 추정이 실측으로 확인됐다.

예정 화면은 `총 N건` 표기가 아예 없어(함정 ③) 첫 장 행수로 갈음했다. 총건수를
안 주는 화면이라 진행 화면만큼 강한 증거는 아니지만, 진행 화면 세 법원이 정확히
일치하고 옥션원 공지·우리 상세 6,000건 표본과도 맞아 결론은 같다.

## 고친 뒤 확인했다

`_open_search_page` 로 화면을 열면 **열자마자 '전체'가 눌려 있다**(진행·예정 모두).
그 상태로 검색한 건수는 서울중앙 223 · 부산 271 — 기일입찰 때와 같다.

다시 확인하려면:

```bash
PLAYWRIGHT_BROWSERS_PATH=.playwright-browsers .venv/bin/python scripts/g09_check_bid_type.py
```

**기간입찰이 재개되면 이 스크립트가 처음 갈라진다.** 건수가 다르면 0이 아닌 값으로
끝나고 어느 화면·어느 법원인지 찍는다.

## 어떻게 고쳤나

`SearchPageConfig` 에 `bid_type_all_input_id` 를 얹고, 폼이 준비된 직후
(`_wait_for_search_form` 끝)에 한 번 누른다. 화면 4종 분기 방식과 같은 모양이다.

**라디오 input 자체는 가려져 있어 Playwright가 못 누른다. 라벨을 누른다.**
WebSquare는 신뢰된 클릭만 받으므로 JS로 `checked` 를 세우면 값만 바뀌고 화면이
모르는 상태가 된다(`_go_next_page`·G08과 같은 문제).

못 눌러도 검색은 그대로 진행한다. 지금 기간입찰 물건이 0이므로 여기서 수집을
멈추는 것이 더 나쁘다.
