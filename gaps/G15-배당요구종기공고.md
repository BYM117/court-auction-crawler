# G15. 배당요구종기공고 — 기일 몇 달 전 물건을 법원이 공개하는데 우리는 0% 본다

**상태**: **수집 시작됨** (2026-09-18, 세션 B) · **담당**: 세션 A→B · **우선순위**: **최대 격차**

## 한 줄
**`CLAUDE.md`의 "공고 전 물건은 홈페이지 어디에도 없다"가 틀렸다.** 있다.

## 원인 — 아무도 그 화면을 안 열어봤다

`경매공고 > 배당요구종기공고`(`PGJ141M00&pgjId=142M01`)에 **경매개시결정된 사건**이 뜬다.
화면 유의사항이 명시한다.
> *"**조회된 사건들은 경매개시 결정이 되었으므로** 배당을 받아야 할 채권을 가지고 있는
> 채권자는 배당요구의 종기까지 …"*

```
경매개시결정 → 배당요구종기 공고 → (감정평가) → 매각공고(기일 14일 전) → 매각기일
     ↑ 여기서 이미 공개된다                        ↑ 우리는 여기부터 본다
```

## 결과 (실측 2026-09-16, 서울중앙지방법원 **경매1계 한 계**)

| | |
|---|---|
| 공고에 뜬 사건 | **73건** |
| 우리 DB에 있는 것 | **0건** |
| 우리 DB에 없는 것 | **73건 (100%)** |

날짜 범위 2026.07.01 ~ 2026.11.23. 예:
```
서울중앙지방법원 2026타경101257
  소재지    서울특별시 관악구 남현동 602-18 화인오피스텔 7층706호
  경매개시  2026.07.01
  공고일    2026.07.08
  배당요구종기 2026.09.16
```
**7월 1일에 개시된 물건을 9월 16일 현재까지 우리는 모른다.**

## 규모 추정
서울중앙 경매1계 하나가 73건이다. 법원 60개, 법원마다 경매계가 여럿
(서울중앙은 1~12계와 21계, 보존계까지). 보수적으로 법원당 5계 × 50건이면 **1만 5천 건 규모**.
**옥션원과의 4천 건 격차보다 크다.**

## 이 화면이 주는 칸
```
사건번호 · 소재지 · 소유자 · 공고일 · 담당계 · 부동산등의 표시(목록)
채무자 · 경매개시결정일자 · 배당요구종기일
```

## 한계 — 정직하게
1. **사건 단위다.** 물건번호별 감정가·최저가가 없다. 아직 감정평가 전이라 당연하다.
2. 그래서 이것만으로는 지금 화면에 못 올린다. **사건번호를 얻는 것이 목적**이다.
3. 사건번호를 알면 `경매사건검색(PGJ159M00)`으로 기본정보를 받을 수 있다.
   우리 `detail_crawler`가 이미 하는 일이다.
   단 그 화면은 *"개시결정일로부터 14일이 경과한 사건에 한하여 정보가 제공됩니다"* 제약이 있다.
4. 감정평가서·현황조사서는 **기일 2주 전부터**만 열린다(`G16`).
5. **조회 창을 확인해야 한다.** 배당요구종기일이 지나면 목록에서 빠지는 것으로 보인다
   (표본의 종기일이 전부 오늘 이후였다). 사실이면 **주기적으로 긁어야** 놓치지 않는다.

## 고치는 법
1. `SearchPageConfig`에 배당요구종기공고 화면을 하나 더 만든다.
   검색은 **법원 + 담당계** 단위라 기존 법원 루프에 **계 루프**가 하나 더 붙는다.
2. 여기서 얻은 사건번호를 **"기일 미정" 상태로 DB에 넣고**,
   상세 수집기가 사건 화면에서 기본정보를 채우게 한다.
   매각기일이 잡히면 기존 진행/예정 파이프라인이 이어받는다.
3. **웹 payload는 건드리지 않는 편이 안전하다** — 기일·감정가가 없는 물건을 기존 목록에
   섞으면 화면이 깨진다. 별도 상태(`예고`/`개시`)로 두고 웹과 합의한 뒤 노출한다.

## 확인
```
경매공고 > 배당요구종기공고 → 법원/담당계 선택 → 검색
서울중앙지방법원 + 경매1계 → 73건 (2026-09-16 기준)
```

## 구현 (2026-09-18, 세션 B)

### 검색 단위를 실측으로 정했다 — 법원만으로는 안 된다

| 방식 | 결과 |
|---|---|
| 법원만 (담당계 비움) | ❌ **첫 계만** 나온다 |
| 법원 × 담당계 | ✅ 확인됨 |
| 소재지 시/도만 | ❌ 결과표 안 나옴 |
| 소재지 시/도+시/군/구 | ❌ 결과표 안 나옴 |

담당계를 비우면 자동으로 경매1계가 선택된다. **9/16에 잰 '경매1계 73건'과
9/18에 잰 '법원 검색 73건'이 같았던 것은 우연이 아니라 같은 것을 두 번 센 것이다**
(`CLAUDE.md` 함정 ⑤-1). 계별 합으로 확인했다.

```
서울중앙 담당계 안 고름 → 73건
경매1계 73 · 2계 24 · 3계 29 · 4계 33 · 5계 0   → 5개만 159건
```

### 결과표는 한 건이 두 줄이다

```
6칸 행: 사건번호 · 소재지 · 소유자 · 공고일 · 담당계 · '목록'
3칸 행: 채무자 · 경매개시결정일자 · 배당요구종기일
```

`parse_rows`가 묶는다. 두 가지를 못 박았다(`tests/test_notices.py`).
- **짝이 없어도 사건을 안 버린다.** 종기일을 못 읽었다고 사건번호까지 놓치면 더 나쁘다.
- **다음 사건의 머리를 짝으로 삼지 않는다.** 3칸 행이 빠졌을 때 옆 건 값을 끌어오면
  조용히 틀린 데이터가 된다.

### 별도 테이블에 쌓는다

`auction_notices (court, case_no, address, owner, debtor, notice_date, dept,
opened_at, dividend_deadline, first_seen_at, last_seen_at)`.

**`auction_items`에 섞지 않는다.** 기일도 감정가도 없는 사건을 목록에 넣으면 웹이
깨진다(이 문서가 원래 경고한 그대로). 별도 테이블이라 다운스트림 위험이 없다.

### 결과 (서울중앙지방법원 한 곳, 2026-09-18)

| | |
|---|---|
| 경매계 | 25개 (그중 **14개가 0건**) |
| 수집 | **376건** |
| 빈 칸이 있는 행 | **0건** |
| **물건 목록에 없는 사건** | **376건 (100%)** |

개시일 분포: 2026.09 65 · 08 167 · 07 133 · 06 8 · 05 1 · 04 1 · 03 1.
가장 최근 건은 **개시 9/14 → 9/18 인지**. 매각공고를 기다렸으면 몇 달 뒤다.

### 추정이 사실로 확인됐다 — 놓치면 영구 손실이다

이 문서가 *"종기일이 지나면 목록에서 빠지는 것으로 보인다"* 고 추정했던 것을 쟀다.

> **376건 중 배당요구종기일이 오늘 이전인 것 0건.**

낙찰가(함정 ⑥)·법원문서(함정 ⑦)와 같은 성격이다. **주기 수집이 선택이 아니다.**

### 운영

`com.court-auction.notices` — 매일 05:40. 개시결정 후 몇 달짜리 일정이라 3시간
사이클에 얹을 이유가 없고, 법원 60곳 × 경매계라 무겁다.

```bash
PYTHONPATH=src .venv/bin/python -m court_auction_crawler.cli collect-notices --gap
```
`--gap` 은 수집 없이 **공고에는 있는데 물건 목록에 없는 사건**만 센다. 이 격차 자체다.

### 남은 것

- **전국 수집을 아직 안 돌렸다.** 서울중앙만 376건이다.
- 0건인 (법원,계)를 **기억하지 않는다.** 지금은 매번 전수를 돈다. 25계 중 14개가
  0건이었으니 기억하면 호출이 절반 이하로 준다.
- 사건번호를 상세 수집기에 넘기는 연결이 **아직 없다.** 사건 화면은
  *"개시결정일로부터 14일 경과"* 제약이 있어 그 시점을 봐야 한다.
- 웹 노출은 안 한다. 기일·감정가가 없어 기존 목록에 섞으면 화면이 깨진다.
