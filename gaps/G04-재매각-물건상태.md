# G04. 재매각 물건이 화면에서 구별 안 된다 — 보증금이 2배인데

**상태**: **해결됨** (B 2026-09-17) · 남은 것은 웹 표시(→ `G13`) · **담당**: 세션 B
**묶임**: G01 · G05와 같은 데이터. **한 번에 파싱할 것.**

## 한 줄
지금 입찰 가능한 1,312건이 과거에 낙찰됐다 깨진 물건인데, 목록엔 그냥 `유찰 N회`로 나온다.

## 왜 돈 문제인가
**재매각 물건은 매수신청보증금이 최저가의 20%다**(보통 10%).
비고에 '재매각'이 있는 활성 423건 중 **423건 전부**가 20%를 같이 적고 있다. **예외 없다.**
모르고 가면 보증금 부족으로 **입찰이 무효**가 된다.

## 원인
`enrichment.parse_special_rights`의 재료가 **목록 비고와 주소뿐**이다(`enrichment.py:274`).
상세의 기일내역·물건상태를 안 본다.

## 결과 (활성 32,132건 중)

| 이력 | 건수 |
|---|---|
| 과거에 낙찰됐던 물건 | **1,312** |
| 대금미납 | 1,074 |
| 매각불허가 | 213 |
| 매각허가취소 | 32 |
| 비고에 '재매각' (딱지가 붙는 것) | 419 |

**893건은 딱지 없이 '유찰 N회'로만 보인다.**

## 고치는 법 — 기일내역 파싱이 필요 없다

사건 화면의 **`물건상태`** 한 필드에 전체 이력이 문자열로 들어 있다.
**물건 단위라 형제 물건이 안 섞인다.** 표본 6,000건 중 **5,851건(97.5%)** 이 이미 갖고 있다.

| 물건상태 | 건수 |
|---|---|
| `매각준비 -> 매각공고` | 3,448 |
| `매각준비 -> 매각공고 -> 유찰` | 1,819 |
| `매각준비 -> 매각공고 -> 매각 -> 매각허가결정 -> 대급납부` | 353 |

## ★ 고침 (2026-09-17, 세션 B) — 다만 전제 하나가 틀렸다

### ① '재매각이면 보증금 20%'는 참이 아니다

이 문서는 "비고에 '재매각'이 있는 활성 423건 중 423건 전부가 20%"라고 적었다.
파서를 만들어 **물건내역의 실제 보증금 금액**으로 다시 재니 다르다.

| 비고에 '재매각'이 있는 활성 물건의 실제 보증금 | 건수 |
|---|---|
| 최저가의 **20%** | 302 |
| 최저가의 **10%** (안 오른 것) | 78 |
| 최저가의 **30%** | **37** |

**27%에서 틀린다.** 30%짜리 37건은 20%로 안내하면 그대로 입찰 무효다.
20%는 대금미납 직후 회차에 붙고, 그 뒤 유찰이 쌓이면 10%로 돌아가는 것으로 보인다.

→ **비율을 추정하지 않는다.** 법원이 물건내역에 적어 둔 **금액을 그대로 싣는다.**
재매각 이력은 그것대로 따로 싣는다. 둘은 겹치지만 같지 않다.

### ② 뽑은 것 (활성 33,384건, 물건상태 확보 99.9%)

| | 건수 |
|---|---|
| 재매각 (대금미납 388 · 매각불허 74) | **462** |
| 보증금이 10%를 넘는 물건 | **641** |
| 둘 다 | 208 |

### ③ payload (더한 필드라 웹은 안전하다)

```json
"auction": {
  "resale":  {"is_resale": true, "reason": "대금미납", "status_flow": "매각준비 -> … -> 대금미납"},
  "deposit": {"amount": 1711400, "rate": 0.2}
}
```
`special_rights`에도 `재매각`이 붙는다(물건상태 기준). **`deposit.rate`가 0.1을 넘으면
화면에서 경고해야 한다** — 이게 이 격차의 알맹이다(세션 D, `G13`).

### ④ 목록에서 보이게 하려면 컬럼이어야 했다

목록 조회(`ITEM_LIST_SELECT`)는 `detail_json`을 일부러 안 읽는다(763MB). 상세 payload에만
넣으면 **목록에서 구별이 안 된다** — 이 격차가 원하는 게 바로 목록 구별인데. 그래서
`save_item_detail`이 저장할 때 `resale_reason`·`item_status_flow`·`deposit_amount`·
`deposit_rate`·`item_note` 컬럼으로 뽑아 둔다(좌표·공시가격과 같은 방식).
이미 받아둔 상세는 `scripts/backfill_case_item_fields.py`로 채운다 — 법원 사이트를
다시 두드리지 않고 손에 있는 JSON만 다시 읽는다.
