# G14. screening의 '낮음'은 도달 불가능한 분기다

**상태**: 진행 중 — **라이브 재업로드 중**(2026-09-23 시작, 활성은 약 4사이클 ≈ 하루) · **담당**: 세션 B
남은 양은 `python3 scripts/status.py` 의 G14 줄이 직접 센다(0 이 되면 ✅). 아래 '2026-09-23' 참조.
**~~여기서 고치지 말 것~~ → 사용자가 기준을 정해서 구현했다.**

## 한 줄
경고가 전부 울려서 아무것도 안 알린다. 그리고 `낮음`은 **구조적으로 나올 수 없다.**

## 원인 — 코드로 증명된다

`enrichment.build_screening`:
```python
score = 50                     # 50에서 시작
if fail_count:        score -= min(fail_count * 4, 24)
if 최저가율 <= 30:     score -= 12   (또는 <=50 이면 -6)
if 지분:              score -= 15
if 주소 불명:          score -= 10
if 가격 없음:          score -= 8
if 종료성 상태:        score -= 20
flags.append("권리확인 필요")   # ← 조건 없이 무조건
risk_level = "낮음" if score >= 65 else "보통" if score >= 40 else "높음"
```

**모든 분기가 `-=` 뿐이고 `+=`가 하나도 없다. 최대 점수가 50인데 `낮음`은 65 이상이다.**

## 결과 (활성 400건 무작위 표본)

| risk_level | 비중 |
|---|---|
| 높음 | 52% |
| 보통 | 48% |
| **낮음** | **0%** |

| flag | 400건 중 |
|---|---|
| `최저가율 N%` | **400 (전부)** |
| `권리확인 필요` | **400 (전부)** |
| `유찰 N회` | 355 |
| `지분 매각 의심` | 23 |
| `주소 확인 필요` | 1 |

**모든 물건에 붙는 경고는 정보량이 0이다.** 화재경보기가 24시간 울리는 것과 같다.
오히려 변별력 있는 신호(`지분 매각 의심` 23건)를 묻는다.

**웹이 이걸 화면에 쓰고 있다** (`app/items/[id]/page.tsx`, `lib/types.ts`).

## 왜 여기서 안 고치나

> 2026-09-16 사용자 방침: *"위험도는 기록하고 새 세션에서 확실한 기준을 다시 잡는 게 좋겠다."*

점수 공식을 손보는 것은 **버그 수정이 아니라 기준 설계**다.
무엇을 위험으로 볼지, 가중치를 어떻게 줄지는 경매 도메인 판단이 필요하고,
급하게 숫자만 바꾸면 또 다른 엉터리가 된다.

**→ `../SCREENING-REDESIGN.md`에 설계 재료·원칙·먼저 답할 질문을 모아뒀다. 거기서 시작할 것.**

## 참고용 응급 조치안 (설계 전에는 적용하지 말 것)
1. `낮음` 임계값을 도달 가능한 값으로 내리거나 가점 항목을 만든다.
2. `flags.append("권리확인 필요")`의 무조건 append를 없앤다.
   경매는 전부 권리확인이 필요하므로 **서비스 전체의 고지사항**이지 물건별 정보가 아니다.
3. `최저가율 N%`도 flag가 아니라 값이다. 이미 `price.minimum_bid_percent`에 따로 있다.
4. 남는 진짜 flag: `지분 매각 의심`·`주소 확인 필요`·`가격 정보 확인 필요`·`종료성 상태`.

## 2026-09-18 재측정 (세션 B) — 달라진 것 없음. **그래서 손대지 않았다**

활성 무작위 400건을 `public_auction_summary` 로 다시 냈다.

| | 2026-09-16 | 2026-09-18 |
|---|---|---|
| 높음 | 52% | 53% |
| 보통 | 48% | 47% |
| **낮음** | **0%** | **0%** |
| `최저가율 N%` | 100% | **100%** |
| `권리확인 필요` | 100% | **100%** |
| `지분 매각 의심` | 6% | 6% |

코드도 그대로다 — `build_screening` 에 `+=` 가 **하나도 없고**, 최대 50점인데
`낮음` 은 65점 이상을 요구한다. 도달 불가능한 분기다.

**오늘(9/18) 다른 격차를 전부 손보면서도 이것만 남긴 이유**는 이 문서에 적힌
사용자 방침 때문이다 — *"새 세션에서 확실한 기준을 다시 잡는 게 좋겠다"*, 그리고
응급 조치안에 붙은 *"설계 전에는 적용하지 말 것"*.

임계값을 내리거나 깃발을 지우는 것은 **한 줄이면 되지만 기준을 정하는 일**이다.
무엇을 '낮음' 으로 부를지 안 정한 채 숫자만 맞추면 이 문서가 경고한 '또 다른
엉터리' 가 된다. `../SCREENING-REDESIGN.md` 에서 시작할 것.

## 2026-09-21 해결 (데이터측) — '권리상 함정만' 으로 재설계

**사용자가 기준을 정했다**(질문에 답): *위험도 = 권리상 함정만.* 지분·대항력/선순위
임차인·인수되는 권리·특수권리만 본다. 유찰·최저가율·주소·가격은 값·데이터품질이라 뺐다
(잃는 값 없음 — 각각 `fail_count`·`price.minimum_bid_percent`·`coordinate_quality`·
`price` 에 이미 따로 있다).

`enrichment.build_screening(rights_flags)` 으로 바꿨다. 이미 뽑아 둔 특수권리 목록
(`special_rights`)에서 등급을 낸다:
- **높음**: 유치권·법정지상권·대항력있는임차인·선순위임차인·별도등기·지분매각·분묘기지권
- **보통**: 맹지·농지취득자격증명·위반건축물·제시외건물·재매각·형식적경매
- **정보성(등급 미반영)**: 일괄매각·공유자우선매수 — 절차·구조지 권리 함정이 아니다
- 함정 없으면 **낮음**(옛 설계의 도달 불가능 분기가 자연히 풀렸다)

**실측 (활성 500건)**

| | 옛 | 새 |
|---|---|---|
| 높음 | 52% | 12% |
| 보통 | 48% | 36% |
| 낮음 | **0%** | **51%** |
| 근거 flag | `권리확인 필요`·`최저가율` 100%(잡음) | 지분매각 8%·제시외 20%·농취증 26% 등(변별력) |

셋 다 갈리고(원칙 ③ 충족), `flags` 는 등급을 만든 함정만 담아 화면이 '왜' 를 보인다.

### 아직 안 한 것 — 세션 D/E 가 할 것 (경계 규칙)
1. **웹 표시 반영.** `screening.flags` 내용이 바뀌었다(무조건 `권리확인 필요` 사라짐,
   이제 실제 권리함정만). `권리확인 필요` 는 **서비스 전체 고지사항**으로 화면 하단에
   옮긴다(원칙 ①). `최저가율` 은 `price.minimum_bid_percent` 값을 쓴다.
2. ✅ **(09-23 진행 중)** ~~**라이브 재푸시.**~~ 코드만 바뀌면 R2 엔 안 온다(함정 ②). 기존 물건에 새 위험도를
   퍼뜨리려면 `web_sync` 의 `kind='item'` 행을 비워 후보로 되돌린다. R2 업로드라
   **법원 부하는 0** 이지만, 웹이 새 내용에 맞춰진 뒤에 하는 게 안전하다.
3. **심각도 조정(선택).** 높음/보통 배정은 표준 경매지식 기반 제안이다. 특히
   농취증(보통, 26%로 흔함)·제시외(보통, 20%)를 정보성으로 내릴지 사용자와 정한다.

~~**수집 데몬은 일부러 이 변경으로 재시작하지 않았다**~~ **(09-23 재시작함 — 아래 절)** — 재시작하면 새로 미는 물건만
새 위험도가 되어 라이브가 섞인다. 웹이 준비되면 그때 재시작+재푸시를 함께 한다.

## 2026-09-23 — 라이브 반영 시작. 깃발은 비우고 이유는 `reasons` 로 (사용자 결정)
