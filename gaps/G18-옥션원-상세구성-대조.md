# G18. 옥션원 상세 한 장을 뜯어 우리와 대조했다

**상태**: 조사 완료 (2026-09-18, 세션 B) · **담당**: B(추출) + D(표시)

## 어떻게 봤나

사용자 안내대로 **옥션원 메인의 공개 샘플**을 봤다(`/auction/ca_sample.php` →
`ca_view.php?product_id=…&sample_key=1`). 로그인 없이 누구나 볼 수 있는 한 장이다.

> 이전 조사에서 나는 *"옥션원도 감정평가서 텍스트를 긁는 것"* 이라고 **확인 없이
> 단정**했다. 사용자가 직접 뜯어보고 아니라고 알려 줬다. 이번엔 실제로 열었다.

## 옥션원이 한 장에 담는 것

```
① 머리    사건번호 · 법원 · 매각기일(요일·시각) · 경매계(전화번호)
② 주소    소재지 + **새 주소(도로명)**
③ 가격    물건종별[공급평형] · 감정가 · **평당 단가[전용]**
④ 관심    **오늘조회 13 · 2주누적 69 · 2주평균 5**
⑤ 기일표  1차 2026-08-26 363,000,000 유찰
          2차 2026-10-02 254,100,000
          3차 2026-11-06 177,870,000   ← **아직 안 잡힌 기일을 계산해서 보여준다**
          4차 2026-12-08 124,509,000
⑥ 제원    대지권 · 최저가(70%) · 건물면적 · 보증금(10%) · 일괄매각 여부
⑦ 당사자  소유자 · 채무자 · 채권자 · 개시결정일 · 사건명
⑧ 관련사건 2018타경505939(소유권이전)
⑨ 탭     사진 / 건물등기 / 감정평가서 / 현황조사서 / 매각물건명세서 /
          세대열람내역서 / 부동산표시목록 / 기일내역 / 문건송달 / 사건내역 /
          전자지도 / 전자지적도 / **로드뷰** / 씨리얼지도 / 도시계획지도
⑩ 물건현황 **감정원명 · 가격시점 · 보존등기일** / 목록별(구분·사용승인·면적·
          이용상태·감정가격·기타) · 비준가격 · 난방설비
⑪ 현황위치 요항표 내용(위치·교통·형상·접도)
⑫ 임차인  **말소기준권리 · 배당요구종기일 · 예상배당표** · 임차인 유무
⑬ 기타    현황조사 메모("폐문부재로 소유자를 만날 수 없어 안내문 부착")
⑭ 등기부  **채권액합계** · 권리종류·권리자·채권금액·**소멸여부**
```

## 우리와 대조

### 이미 있는 것 (payload 에 나감)

| 옥션원 | 우리 |
|---|---|
| 사건번호·법원·기일 | `case_no` `court` `sale_date` |
| 소재지 | `address` (도로명은 원문에 포함) |
| 감정가·최저가·최저가율 | `price.*` |
| **평당 단가** | `price.appraisal_per_pyeong` · `minimum_bid_per_pyeong` |
| 보증금 | `auction.deposit` (비율까지) |
| **조회수** | `auction.popularity` |
| 소유자·채무자·채권자 | `auction.parties` |
| 사건명 | `auction.case_type` |
| 기일 이력 | `sale_results` · `auction.past_sales` |
| 요항표(현황·위치) | **`property.appraisal_summary`** (2026-09-18 확보) |
| — | **`property.appraisal_facts`** (사실 추출, 옥션원에 없는 것) |
| 지도 | `map` + `coordinate_quality` (등급까지) |
| — | `land_use` · `building` · `transactions` (옥션원은 별도 탭) |

### 갖고 있는데 **안 꺼내는 것** — 여기가 바로 할 일이다

최근 상세 400건에서 원문에 들어 있는 비율이다.

| 항목 | 원문 보유 | payload |
|---|---|---|
| **배당요구종기일** | **100%** | 없음 |
| **관련사건** | **100%** | 없음 |
| **이용상태** | 95% | 없음 |
| **현황조사 메모**(폐문부재 등) | 60% | 없음 |
| **임차인 현황** | 34% | 없음 |
| 사용승인일 | 19% | `appraisal_facts` 에만 |

**추출만 하면 되는 것들이다.** 새로 긁을 필요가 없다.

### 못 얻는 것 (원천)

| 옥션원 | 왜 |
|---|---|
| 등기부현황(권리·채권액·소멸여부) | `CLAUDE.md` "원천적으로 못 하는 것" |
| 예상배당표 | 같음 |
| 세대열람내역서 | 같음 |
| 감정평가서 **PDF 원본** | 협회 서버, 링크도 금지(G06) |
| 감정원명·가격시점·보존등기일 | 원문에 0% — PDF 안에 있는 것으로 보인다 |

### 우리가 만들 수 있는데 안 만든 것

**미래 기일 예측.** 옥션원은 3차·4차를 **아직 안 잡힌 채로 계산해 보여준다**
(363,000,000 → 254,100,000 → 177,870,000 → 124,509,000, 매회 70%).
우리는 유찰 체감률과 기일 간격을 이미 안다. **계산해서 실으면 된다.**
입찰자가 '언제까지 기다리면 얼마가 되나' 를 보는 핵심 정보다.

## 할 일

1. **(B) 배당요구종기일·관련사건·이용상태·임차인·현황조사 메모를 payload 에 꺼낸다.**
   이미 원문에 있다. 추출만 하면 된다.
2. **(B) 미래 기일·최저가를 계산해 싣는다.** 체감률은 법원·물건별로 다르니
   실측으로 확인할 것(우리 `sale_results` 에 재료가 있다).
3. (D) 화면 구성은 옥션원의 한 장 구성을 참고하되, 우리가 더 가진 것
   (`appraisal_facts` · `coordinate_quality` · `land_use` · `transactions`)을 살릴 것.
