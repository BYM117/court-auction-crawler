# G05. 재매각된 물건에 낙찰가가 그대로 남는다

**상태**: **해결됨** (B 2026-09-17) · **담당**: 세션 B
**묶임**: G01 · G04와 같은 데이터.

## 한 줄
**지금 입찰할 수 있는 물건에 "낙찰 ○○원"이 찍혀 있다.** 현재 18건, **앞으로 늘어난다.**

## 원인
`store.record_sale_results`가 매각을 보면 `sold_amount`를 박고 `is_active=0`으로 내린다.
물건이 되돌아오면 `upsert_items`가 상태를 보고 `is_active=1`로 되살리는데
**`sold_amount`·`sold_date`는 초기화하지 않는다.**

`enrichment.build_sold`가 `sold_amount`만 보므로 그대로 화면에 나간다.

## 왜 늘어나는가
대금미납은 **낙찰 30~40일 뒤에 드러난다.** 우리가 낙찰가를 모으기 시작한 게 2026-08-20이라
**첫 미납 주기가 아직 안 돌았다.**

## 고치는 법 — 지우는 게 아니다 (2026-09-16 방향 정정)

> 처음에 "`sold_amount`를 비운다"고만 적었다. **그것만 하면 정보를 버리는 것이다.**

옥션원은 과거 낙찰을 **지우지 않고 이력으로 보여준다.**

```
참고사항 | ▶본건매각 2026.01.19 / 매각가 130,000,000원 / OOO / 1명 입찰 / 대금미납
```

"이 물건은 1억 3천에 낙찰됐다가 대금미납으로 다시 나왔다"는 **입찰자에게 핵심 정보**다.
재매각이면 보증금이 20%로 오르고(`G04`), 직전 낙찰가는 시세의 강력한 단서다.

### 할 일
1. `sold`(현재 낙찰 상태)와 **`past_sales`(과거 낙찰 이력)를 분리한다.**
   - 물건이 다시 활성이 되면 `sold`는 비운다 — 지금 팔린 물건이 아니니까.
   - **동시에 `past_sales`에 `{날짜, 매각가, 결과}`를 남긴다.**
2. 재료는 이미 있다 — `G01`의 사건 기일내역(`매각(21,000,000원)`)과
   `G04`의 `물건상태`(`… -> 매각 -> 매각허가결정 -> 대금미납`).
3. 우리가 못 만드는 것은 **응찰자 수와 낙찰자 이름**뿐이다(법원이 안 준다 → `G10`).
   **날짜·매각가·결과는 전부 만들 수 있다.**

## 확인
```sql
SELECT COUNT(*) FROM auction_items WHERE is_active=1 AND sold_amount IS NOT NULL;  -- 18
```

---

## ★ 고침 (2026-09-17, 세션 B) — 새 필드가 필요 없었다

`past_sales`를 새로 만들려 했는데, **이력은 이미 payload에 있다.**
`auction_sale_results`(기일별 결과, 금액 포함)가 상세 payload의 `sale_results`로 나간다.
그래서 할 일은 하나였다 — **활성 물건의 `sold`를 비우는 것.**

**다만 그냥 비우면 안 됐다.** 18건 중 **6건은 이력 쪽에 금액이 없어서**(결과행은
있는데 금액이 빈 채) 비우는 순간 낙찰가를 영영 잃는다. 그래서 `retire_sale`은
**이력에 먼저 넣고**(이미 금액이 있으면 그대로 둔다 — 결과 화면 값이 더 정확하다)
비운다.

은퇴 조건은 **새 기일 > 낙찰일**이다. 낙찰 직후 아직 처리 중인 물건을 건드리지
않기 위해서다(`backfill_sale_results`의 되살아남 방지 가드와 같은 뜻).

18건은 **다음 목록 수집 때 스스로 정리된다.** 활성 물건이라 매 사이클 upsert를 거친다.

회귀 테스트 3개: `tests/test_store.py::StoreTests::test_revived_item_moves_its_sale_into_history`
외 2개(이미 있는 금액을 안 덮는다 · 처리 중인 낙찰은 안 건드린다).

## 함정
payload에 **필드를 더하는 것은 안전**하고, 이름을 바꾸거나 빼는 것은 웹과 합의해야 한다.
`past_sales`는 새 필드라 안전하지만, `sold`를 비우는 것은 **웹의 `settledSale()` 동작에 영향**을 준다.
