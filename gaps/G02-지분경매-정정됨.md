# G02. ~~지분경매에 딱지가 없다~~ → **정정: 이미 잡고 있었다**

**상태**: **해결됨** (B 2026-09-17) · 남은 것은 웹 표시(→ `G13`) · **담당**: 세션 B

## 한 줄
내가 `SPECIAL_RIGHT_KEYWORDS`만 보고 단정했다. **실제 payload에는 이미 들어 있다.**

## 무엇이 틀렸나

처음 보고: *"지분경매 2,497건에 딱지가 없다. `SPECIAL_RIGHT_KEYWORDS`에 `지분`을 한 줄 추가하면 끝."*

실제 payload를 만들어보니:

```json
"property": {"share": {"is_share_sale": true, "fraction": "103/105", "raw": "..."}}
"screening": {"flags": ["지분 매각 의심", "유찰 5회", "최저가율 16%"], "risk_level": "높음"}
```

**두 군데에서 이미 잡고 있었다.**

## 교훈 (다른 항목에도 적용)
**코드 한 군데를 보고 단정하지 말 것. 결과물(payload)을 실제로 만들어봐야 한다.**
`enrichment.py`에 `parse_share_info`가 따로 있는데 키워드 목록만 보고 없다고 했다.

## 남은 것 (작다)
1. ~~`auction.special_rights` 배열에는 안 들어간다.~~ → **넣었다(2026-09-17).**
   `is_share_sale`이면 `지분매각` 딱지를 붙인다. 목록 기준 **2,118건**에 붙었다.
   웹이 딱지로 쓰는 배열은 이것 하나라, 다른 데서 이미 아는 사실도 여기 없으면 안 보인다.
2. **웹이 `property.share`를 아예 안 쓴다** → `G13`에서 다룬다.

## 확인
```python
from court_auction_crawler.enrichment import public_auction_summary
# 활성 + raw_json LIKE '%지분%' 인 물건으로 만들어보면 is_share_sale=true가 나온다
```
