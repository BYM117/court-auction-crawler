# G10. 당사자 내역을 100% 갖고도 안 쓴다 + **낙찰자 실명 출처는 아직 모른다**

**상태**: 일부 미해결 · **담당**: 세션 B(기능) / 미제는 조사 필요 · **우선순위**: 중

## 한 줄
사건 화면의 `당사자 내역`을 표본 6,000건 **전부** 갖고 있는데 payload에 안 싣는다.
그리고 **법원은 화면만 가리고 문서 본문은 안 가린다.**

## 원인
사건 기본 내역에 `당사자 내역` 표가 있다.
```
당사자구분   당사자명              당사자구분      당사자명
채권자      에OOOOOOOOOOOOO OOOO   소유자          이OO
채무자겸소유자 이OO                임차인          김OO
교부권자    평OO
```
표본 6,000건 **전부**에 있다. payload에 구조화해서 싣지 않는다.

옥션원은 이걸로 `이해관계인검색`과 `은행별경매물건`을 만든다.
**"채권자가 은행인가 개인인가"는 권리 분석의 출발점**인데 우리는 못 쓴다.

## ⚠ 2026-09-16 정정 — "법원이 가려서 준다"는 반쪽 사실이다

> 내가 *"법원이 이미 마스킹해서 주니 역추적하지 말 것"*이라고 적었다. **화면만 그렇다.**

법원은 **웹 화면의 당사자내역 표만** 가린다(`이OO`). **문서 본문은 전혀 안 가린다.**
우리 문서 본문 1,200건을 훑은 실측이다.

| 문서 | 항목 | 실명 | 가려짐 |
|---|---|---|---|
| 현황조사서 | 임차인 | 5,230 | **0** |
| 매각물건명세서 | 임차인 | 1,732 | **0** |
| 현황조사서 | **소유자** | **443** | **0** |
| 매각물건명세서 | **소유자** | **183** | **0** |
| 현황조사서 | 점유자 | 287 | 0 |
| 매각물건명세서 | **채권자** | 57 | 0 |
| 현황조사서·명세서 | **채무자** | 38 | 0 |

**가려진 것이 한 건도 없다.** 우리는 이 문서들을 이미 갖고 있다
(현황조사서 22,263건, 매각물건명세서 28,651건에 본문 보유).

### 옥션원이 특별한 경로를 가진 게 아니다
옥션원 `이해관계인검색`(`/auction/ca_person.php`)의 이용 안내:
> **소유자, 채무자, 채권자 이름으로 경매물건 찾기**
> 1. **소유자의 이름은 아는데** 사건번호, 주소가 잘 생각이 나지 않을 경우

입력칸이 `owner` · `debt` · `credit` 세 개다. **실명 DB를 갖고 있다는 뜻이고,
출처는 이 문서들일 가능성이 가장 높다. 우리도 같은 원재료를 갖고 있다.**

## ✅ 낙찰자 실명·차순위·응찰자수 — 2026-09-16 조사 완료

**결론: 법원 웹사이트에는 없다. 우리는 못 얻는다. 근거를 아래에 남긴다.**

### 옥션원이 가진 것 (실측)

2026-09-16에 낙찰된 서울남부지방법원 2023타경120378(양천구 목동 다세대)의
옥션원 물건 상세 기일내역:

```
1차  2026-09-16  338,000,000원   매각 : 449,999,990원 (133.14%)
     (입찰3명, 매수인:서초구 김미자 / 차순위금액 389,100,000원)
     매각결정기일 : 2026.09.23
```

- **응찰자 수** (입찰3명)
- **매수인 실명 + 지역** (서초구 김미자)
- **차순위금액** (389,100,000원) ← 2등 금액으로 보인다(미확인, 아래 참고)
- 매각가·매각결정기일

### `person_hide` 토글 — 옥션원은 실명을 DB에 갖고 있다

상세 URL에 `person_hide` 파라미터가 있다.

| URL | 표시 |
|---|---|
| `...&person_hide=0` (기본) | `매수인:서초구 **김미자**` |
| `...&person_hide=1` | `매수인:서초구 **김○○**` |

**가리는 것은 표시 단계일 뿐, 실명을 갖고 있다.**

### 법원 웹에는 없다 — 6개 화면 전수 확인

| 화면 | 매수인명 | 차순위 | 응찰자수 |
|---|---|---|---|
| 매각결과검색 (`PGJ158M00`) | 없음 | 없음 | 없음 |
| 물건상세 기일내역 (5칸) | 없음 | 없음 | 없음 |
| 사건 기일내역 (7칸) | 없음 | 없음 | 없음 |
| **`최근입찰결과`** 칸 | **없음** | 없음 | 없음 |
| 문건처리 내역 | **가림** (`최고가매수신고인 신OO`) | — | — |
| 당사자 내역 | 가림 | — | — |

우리 DB에서 `최근입찰결과` 칸을 가진 물건 20,000건을 훑은 값의 형식이다.
```
2026.07.23 유찰
2025.12.11 매각( 21,000,000원 ) 2025.12.18 최고가매각허가결정
```
**날짜 + 결과 + 금액 + 허가결정까지다. 이름도 차순위도 응찰자수도 없다.**

### 그리고 옥션원이 법원 웹보다 빠르다

같은 사건을 **같은 날** 법원 경매사건검색에서 열어봤다.
```
기일정보 || 2026.09.16 || 최근입찰결과 || (빈칸)
물건상태 || 매각준비 -> 매각공고
```
**법원 웹은 오늘 낙찰을 아직 반영하지 않았는데 옥션원은 이미 갖고 있다.**

### 출처는? — 단정하지 않는다

법원 웹이 아닌 것은 확정이다. 남는 가능성은 **법정 현장(개찰 시 호명 청취)** 또는
**법원·집행관사무소로부터의 직접 데이터 수급**이다.
옥션원 메뉴에 `실시간결과 생중계`가 있고, 표기 형식이
`입찰3명, 서초구 김미자, 매각가 …` / `임태규 외1명`으로 **개찰 호명 형식과 같다**는 점이
현장 쪽을 가리키지만, **외부에서 둘을 구별할 방법이 없다. 추측으로 단정하지 말 것.**

> 앞서 내가 *"법정 현장에서 수집한다"*고 **단정**했던 것은 근거가 없었다.
> 지금은 *"법원 웹에는 없다"*까지만 확정이고 그 너머는 모른다.

### 미확인으로 남기는 것
- **`차순위금액`의 정확한 의미.** 2등 입찰가인지, 차순위매수신고금액인지.
  입찰 1명인 물건에서 이 값이 없으면 2등 입찰가 해석이 맞다. **표본을 더 봐야 한다.**

### 우리에게 주는 의미
**응찰자 수·매수인명·차순위는 못 얻는다**가 유지된다. 다만 **근거가 바뀌었다** —
"옥션원만의 비법"이 아니라 **법원 웹이 그 정보를 공개하지 않는다**는 것이 확인됐다.
`CLAUDE.md`의 "원천적으로 못 하는 것"에 이 셋을 넣을 근거가 생겼다.

## 고치는 법 — 두 갈래를 분리할 것

**1. 기능 (지금 할 수 있다)**
당사자 내역(화면 표, 가려진 것)으로 **채권자 유형 분류**(은행/캐피탈/공공/개인)를 만든다.
개인 식별이 아니라 권리 분석 신호다. `에OOOOOOOOOOOOO OOOO` 같은 값도 유형 판별에는 충분하다.

**2. 정책 (여기서 결정하지 말 것)**
문서 본문의 실명을 어디까지 쓸지는 **기능 문제가 아니라 정책 문제**다.
`../PRIVACY-MASKING.md`가 이미 **"원본은 보관하고 웹에서 가린다 / 낙찰되면 가린다"**로 정해뒀다.
**그 문서를 먼저 읽고, 바꾸려면 거기서 바꿀 것.**
