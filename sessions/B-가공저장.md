## ★ 제일 먼저 알아야 할 것 — 2·3·4번은 한 덩어리다

`G01`(낙찰 금액) · `G04`(재매각 이력) · `G05`(past_sales)가 **전부 같은 데이터에서 나온다.**

```
detail_json['case']['case_tables' | 'filing_and_service_tables' | 'schedule_tables']
   ├ 기일 내역   →  매각(21,000,000원) · 납부(2026.01.20) · 최고가매각불허가결정
   ├ 물건상태    →  매각준비 -> 매각공고 -> 매각 -> 매각허가결정 -> 대금미납
   └ 사건명      →  부동산임의경매 / 강제경매 / 형식적경매
```

**한 번 파싱해서 네 곳(G01·G04·G05·G07)에 쓴다.** 따로 만들면 세 번 헛일한다.

### 파싱 함정 두 개
1. **표가 세 리스트에 흩어져 있다.** 리스트 이름을 믿지 말고 셋 다 훑고 caption으로 찾을 것.
2. **기일 내역 행의 첫 칸은 "이 물건"의 번호가 아니다.** 사건 단위라 형제가 섞인다.
   `(법원, 사건번호, 행의 물건번호)`로 **item_key를 새로 만들어** 붙일 것.
   실측 3,029행 **전부**가 이 물건 번호와 달랐다.
3. **법원 오타 `대급납부`** — `대금`으로 찾으면 353건을 놓친다.

## 함정
- `enrichment.py`는 **순수 함수만** 두는 곳이다. DB 조회를 끌어들이지 말 것.
- payload에 **필드를 더하는 것은 안전**, 이름 변경·삭제는 **웹(세션 D)과 합의**.
  `CLAUDE.md` 경계 규칙.
- **payload 모양이 바뀌어도 R2엔 안 온다.** `pending_item_pushes()`는 시각만 본다.
  전량 재업로드가 필요하면 `web_sync`의 `kind='item'` 행을 지운다. (`CLAUDE.md` 함정 ②)
- `G10`의 **정책 부분(문서 본문 실명)은 여기서 결정하지 말 것.** `PRIVACY-MASKING.md` 소관.

## 공통 규칙 (모든 세션)

1. **한 파일은 한 세션만 만진다.** 남의 파일이 필요하면 그 세션에 요청한다.
2. **코드를 고치는 세션은 워크트리로 격리한다.** 단 격리 작업대엔 `data/`가 안 따라온다 —
   `--db data/auction.sqlite3` 기본값이 cwd 상대경로라 **에러 없이 빈 DB가 새로 생긴다.**
   **DB 조회·수집 명령·데몬 재시작은 세션 C에 부탁한다.**
3. **문서는 `cat >`로 쓰지 말 것.** 남의 세션이 같은 파일을 만들었을 수 있다.
   덧붙일 때는 앵커를 찾아 끼워 넣는다. (2026-09-16에 이걸로 사고 한 번 냈다)
4. **일이 끝난 브랜치는 그때그때 main에 넣는다.** 안 그러면 다음 워크트리가 낡은 코드에서 시작한다.
5. **푸시는 사용자 승인.** 커밋까지는 알아서.
6. **일이 끝나면 `DEVLOG.md` 맨 위에 기록.** 다른 세션이 아는 유일한 통로다.
7. **코드를 고쳐도 데몬은 모른다.** `launchctl kickstart -k gui/$(id -u)/com.court-auction.<이름>`
